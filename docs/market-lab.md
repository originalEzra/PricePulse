# 行情与规则实验台

> V1 历史操作说明：V2-P1 已关闭原共享模拟／回放入口，当前页面显示升级状态。独立模拟操作将在后续阶段提供，当前实现与测试见 [P1 记录](v2-phase-1.md)。

## 使用方式

1. 在模拟行情页选择股票，再选择“关联提醒”。可以直接创建一条新提醒，也可以只观察行情。
2. 选择上涨、下跌、震荡或正常波动模板；详细参数仍可手动调整。
3. 启动后，右侧展示本次所有有效行情点、阈值线及真实状态变化，不另开页面。
4. 上破／下破点用小点和标签标记；重新激活用蓝点；冷却时间段使用淡黄色背景。
5. 悬停、点击或用左右方向键查看时间、报价、相对前一有效报价的变化和规则状态。原始报价含分以下精度时，Tooltip 同时显示四位原值，避免两位显示恰好相同时误解穿越边界。

例如：上破 100、回落到 95 重新激活。一次上涨触发后保持冷却，后续行情回到 95 才恢复监控，再次穿越 100 会出现第二个上破节点。若这次模拟没有回到 95，图上就不会出现重新激活节点。想观察完整周期，可以连续运行上涨、下跌、再上涨实验；每次都处理同一条实际规则的当前状态。

## 真实数据与接口

- 原模拟接口已返回完整 `results`，包含事件 ID、价格、前一有效报价、事件时间和处理结果。前端使用本次响应绘图，最多支持请求上限 1000 点，不用最近 100 条历史代替本次结果。
- 可选请求字段 `ruleId` 关联一条当前用户的规则。后端预先验证所有权和所属股票，逐点处理时与规则修改共享股票行锁，在同一事务中读取匹配前后状态。
- 每点新增可空 `observation`：`ruleId / ruleName / direction / thresholdPrice / rearmPrice / triggerMode / beforeStatus / afterStatus / event / triggerId / version`。只有成功处理的点有观察数据，触发节点必须能关联 `alert_triggers` 中的实际记录。
- 不指定 `ruleId` 时不额外查询规则状态；原有 `matching` 聚合指标和生成算法保留。
- `/replay` 同样支持观察一条规则，此时要求所有行情属于同一股票。原有无观察回放仍支持多股票。
- 行情主页使用已有触发历史接口，按 `quoteEventId` 精确匹配最近有效行情，避免把单纯穿过阈值误认为实际提醒。

## 展示边界

- 一张图聚焦一条规则，避免大量阈值与标签重叠。密集点保留全部节点，标签自动避让；未放下的标签仍可悬停查看。
- 横轴是按时间顺序排列的事件点；行情集中在同一秒时显示序号，否则显示事件时间。横向点距相等，不表示真实时间间隔相等。
- 虚线采用本次初始规则设置。规则若在运行中被其他页面修改，页面会提示配置变化，各点观察数据与触发说明保留实际值。
- 本次状态轨迹保存在这次接口响应及页面中，没有新增状态历史表；刷新后行情主页仍能查询持久化触发点，不宣称能恢复过去每次重新激活的时间。
- 模拟会实际更新共享股票行情和规则，不是前端动画。暂停／完成规则不会因为图上穿过价格而产生新触发。
- 无有效点时不伪造走势；重复与丢弃事件不重复显示状态转换。

## 验证（2026-10-28）

- 前端类型检查与生产构建通过。
- 28 个单元／契约测试、24 个临时 MySQL／Redis 集成测试通过。
- 新增集成验证：上破与下破两种完整循环、冷却中穿越不重复触发、包含边界的重新激活、真实触发 ID 对应原行情、重复／乱序不重画事件、完整模拟逐点响应、规则所有权与股票隔离。
