本轮实际执行了既有可选长实验用例：6000 个价格点完整读取 10 页；250／1000 条同点规则各 25 次实验与替换，旧子记录正确清理，模拟没有改变正式事实。这是临时夹具的软件回归，不能作为实际账户吞吐／最大容量结论。

关键结果：

1. **动态订阅与取消**：目录外 PLTR、两用户共用一次订阅、无规则也接入、一人取消不退订、最后需求取消等待 ACK 才释放名额、迟到 ACK／重加意图／超时与失败重试、持久恢复、原股票连续性和新订阅首笔基线均通过。取消包含 ACTIVE／COOLDOWN／PAUSED／COMPLETED；摘要竞态与事务回滚不留下半取消状态。
2. **取消与正式通知交叉**：真实运行组件接收合成协议帧，经现有 REAL 行情事务／Redis 区间匹配生成两位用户的事实。取消用户 A 的 3 条规则后，用户 B 继续监控；A 取消前已提交的 Outbox 仍可投递、通知仍可查看。B 后续冷却／再激活／触发继续成功；最后 B 取消才发出唯一退订并释放名额。
3. **实际 Broker 与幂等**：以上交叉场景在专用 RocketMQ 中得到 3 条 SENT Outbox／3 条通知；重复投递没有增加同一触发的通知。原通知流水线 4 项全部通过，含 LEGACY 隔离、实际临时 Broker 停机导致 FAILED 保留、恢复后成功送达一次。没有使用正式 Topic 或正式 Broker 做故障。
4. **模拟跳空隔离与幂等**：交叉场景中 345→355 开盘触发实验 ONCE／REPEAT；同 Key 重试不增加点／事件。正式价格、规则状态／版本／生效时间、触发、Outbox 和通知均未因模拟变化。本人真实订阅／规则取消后，已冻结实验继续运行且保持隔离。
5. **跨页与恢复**：开盘 1 点＋十小时 600 点完整读出 #1–#601，第一价格页 541 点、第二页 60 点；旧开盘重试仍返回原单点批次，只有一条一次性触发。普通／跳空两个真实 Java 进程之间的恢复也通过，清空临时 Redis、修改临时缓存后不改变冻结输入或重复开盘。
6. **备份／迁移演练**：真实 mysqldump 生成约 30 KB 的合成 V8 SQL，完整性与 SHA-256 已记录，以 600 权限保存并恢复到另一个空临时库。逐行校验 16 张原 V8 表的原列数据，包含已提交触发／通知及模拟行；两份库分别执行 V9、V10 后原事实保持。默认目标 PENDING、15 名额、旧用户一次性需求、新用户不自动补回和取消不被重启覆盖均通过。

新 Broker 项目名为 `pricepulse-v2-p5-v21-stage4-20261030`，只占测试端口 39876／38111／38109。独立 MySQL／Redis 使用 Testcontainers；正式接入未参与故障。全部测试资源已清理。

## 测试复现口径

`./mvnw -Pintegration -Dpricepulse.p5.capacity=true verify` 覆盖 134 个单元和 107 个 `*InfrastructureIT`；另 8 个专项分别来自正式消息流水线 4 项、交叉交付 1 项、普通／跳空进程恢复各 1 项和备份迁移恢复 1 项，总计 115 个不同集成。不是把重跑次数累计成测试数。

专项需要独立 Broker，先确认 39876／38111／38109 测试端口空闲；不要改用正式 NameServer。以下是复现指令，最终封版本轮没有再次制造 Broker 故障：

```bash
docker compose -p pricepulse-v2-p5-v21-repro -f deploy/p5/compose.yaml up -d --wait
# 核对实际测试容器名；默认 Compose 命名如下，必须以 pricepulse-v2-p5- 开头。
ROCKETMQ_NAMESERVER=127.0.0.1:39876 \
PRICEPULSE_P5_BROKER_CONTAINER=pricepulse-v2-p5-v21-repro-broker-1 \
./mvnw -Pintegration \
  -Dit.test=NotificationPipelineIT,V21DeliveryRegressionIT,SimulationRestartIT,SimulationGapRestartIT,SubscriptionRolloutRehearsalIT \
  verify
docker compose -p pricepulse-v2-p5-v21-repro -f deploy/p5/compose.yaml down
```

Testcontainers 创建独立 MySQL／Redis；上述测试的供应商接入关闭，受控行情只在夹具库中处理。普通／跳空恢复测试会启动测试 JAR，不使用私人 IDEA 环境。没有给定正确的临时 Broker 容器时，停 Broker 专项会跳过，此时不能复述本轮的“零跳过”。
