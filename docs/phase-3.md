# Phase 3：行情接入、回放与确定性模拟

状态：**已完成（2026-10-25）**

## 目标与边界

Phase 3 建立统一行情入口，能够记录实时行情、回放历史行情并生成可重复的模拟行情，同时对重复、过期、未来和乱序事件给出确定结果。

本阶段只负责推进每只股票的最新价格水位，不查询提醒规则，也不生成触发记录或通知。这些能力分别属于 Phase 4 和 Phase 5。

## 核心决策

### 1. MySQL 保存行情事实与最新水位

- `quote_events` 保存每个首次见到的行情事件及其处理结果。
- `stocks.latest_price` 和 `stocks.latest_quote_at` 保存当前被接受的最新行情。
- `event_key` 有数据库唯一约束，是重复事件的最终防线。
- 丢弃事件也落库并保存原因，后续可以审计、统计和对账。

### 2. 同一股票串行推进

处理一条行情时，事务先通过 `SELECT ... FOR UPDATE` 锁定对应股票行，再读取其最新行情时间并作判断。

因此同一股票的并发请求会串行竞争水位；事件时间不严格晚于当前水位时只能记为乱序，不能把最新价格倒退。不同股票锁不同的行，可以并行处理。

这一设计优先保证 Phase 3 的确定性和可解释性。Phase 7 再通过压测判断单只热门股票是否需要分区队列等更复杂方案，而不是提前增加架构。

## 处理结果

| 结果 | 条件 | 是否插入行情记录 | 是否更新股票最新价 |
| --- | --- | --- | --- |
| `PROCESSED` | 通过全部校验且事件时间推进水位 | 是 | 是 |
| `DUPLICATE` | `eventKey` 已存在且请求内容完全相同 | 否，返回原事件 | 否 |
| `DISCARDED_STALE` | 实时事件早于当前时间 2 分钟以上 | 是，原因 `STALE` | 否 |
| `DISCARDED_FUTURE` | 实时事件晚于当前时间 30 秒以上 | 是，原因 `FUTURE` | 否 |
| `DISCARDED_OUT_OF_ORDER` | 事件时间不晚于该股票当前水位 | 是，原因 `OUT_OF_ORDER` | 否 |

实时阈值位于 `price-pulse.market.live-max-age` 和 `price-pulse.market.max-future-skew`，默认分别为 `PT2M` 与 `PT30S`。

如果复用已有 `eventKey` 却改变股票、价格、事件时间、来源或序号，接口返回 409。这样真正的网络重试可以幂等成功，错误复用键则不会被掩盖。

## API

以下接口都需要 access JWT。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `POST` | `/api/market/quotes` | 接入一条实时行情并应用全部异常策略 |
| `POST` | `/api/market/replay` | 最多批量回放 1000 条历史行情 |
| `POST` | `/api/market/simulate` | 生成并处理 1 至 1000 步模拟行情 |
| `GET` | `/api/market/stocks/{stockId}/quotes?limit=` | 查看某只股票的行情处理历史 |

接口中的 `eventTime` 和 `startTime` 使用 ISO-8601 本地日期时间并约定为 UTC，例如 `2026-10-25T10:30:00.123456`。

## 实时、回放与模拟的差别

- **实时接入**：检查过期、未来、重复和乱序。
- **历史回放**：历史数据天然早于现在，因此绕过过期和未来检查；仍检查重复与股票内部顺序。
- **模拟行情**：调用方明确给出 `runKey`、随机种子、初始价和开始时间。同一组输入生成相同的事件键、价格和时间。重复运行时已有事件全部返回 `DUPLICATE`，不会重复改价。

模拟模式包括：

- `NORMAL`：每步随机上涨或下跌。
- `RISE`：每步向上变化。
- `FALL`：每步向下变化，最低价格为 `0.0001`。
- `OSCILLATE`：上涨与下跌交替，用于构造阈值附近震荡。

`stepRatio` 大于 0 且不超过 20%，价格最终统一为 4 位小数。

## 已验证场景

- 默认离线测试：7 个通过。
- MySQL/Redis 集成测试：5 个通过。
- Phase 3 真实链路覆盖：未认证访问、实时接受、重复幂等、幂等键载荷冲突、过期丢弃、未来丢弃、乱序丢弃、最新价不被异常事件覆盖、历史回放、回放内部乱序、确定性模拟和相同 `runKey` 重跑。
- Flyway 迁移、Phase 2 注册登录和用户规则生命周期继续回归通过。
- RocketMQ 回归测试继续独立运行；Phase 3 尚未把行情直接发送到 MQ。

## 当前限制

- 批量回放和模拟通过同步 HTTP 请求执行，最多 1000 条，适合功能验证和小规模实验。
- 单只股票通过数据库行锁保证顺序；尚未对单只热门股票做吞吐优化。
- `quote_events` 尚未实现归档或自动清理。
- 当前只推进最新价格，不进行阈值匹配。

Phase 4 将使用当前行情的旧价格与新价格计算穿越区间，通过 Redis ZSet 找出候选规则，再由 MySQL 状态机完成最终业务判定。
