# Phase 6A：Vue 3 Web 与端到端联调

## 目标

在不改变后端模块边界的前提下，为现有 API 增加一个可操作的 Web 界面，并验证真实业务闭环，而不是制作只展示静态假数据的页面。

## 技术选择

- Vue 3 + TypeScript + Vite：独立前端工程，快速开发并保留类型检查。
- Vue Router：登录页、行情与规则、通知中心、模拟行情四个页面。
- Pinia：只管理跨页面 JWT 会话，不把所有服务端数据复制成全局状态。
- 原生 SVG：当前只需要轻量折线走势，没有引入 ECharts。
- Vite Proxy：开发环境将 `/api` 转发到 Spring Boot `18080`，不扩大后端 CORS 配置。
- 无 UI 组件库：页面规模较小，避免为少量表单和卡片引入重依赖。

## 页面能力

### 登录与注册

- 调用后端注册和登录接口。
- 本地保存 access JWT，并为受限路由增加登录守卫。
- API 返回 401 时清除失效会话并回到登录页。
- 退出时调用后端说明性接口，然后删除客户端 Token。

### 行情与提醒

- 展示演示股票、最新价格与近期有效行情。
- 按股票查看已有提醒规则。
- 创建、修改、暂停、恢复和删除规则。
- 前端提前校验重复提醒的重新激活价，但后端仍是最终校验边界。
- 金额、状态和触发方向转换为用户可读文案。

### 通知中心

- 查询全部、未读或已读通知。
- 展示不可变触发快照中的股票、价格和事件时间。
- 点击未读通知幂等标记为已读。

### 模拟行情

- 选择股票、模式、步数、随机种子、初始价格和波动比例。
- 调用真实模拟接口并展示处理、重复和丢弃数量。
- 使用唯一 `runKey` 避免实验之间意外去重。

## 已验证的真实闭环

1. 浏览器登录本地测试账户。
2. 为 `DEMO001` 创建“上破 100”的一次性提醒。
3. 从 95 开始生成 10 个上涨行情事件。
4. 10 个事件全部成功处理，规则实际穿越阈值。
5. 后端在同一事务写入触发记录和 Outbox。
6. RocketMQ 消费者生成一条站内通知。
7. 通知中心展示触发价 `100.1632`，并成功标记已读。

这次验证同时覆盖了 Vue 表单、Vite 代理、JWT、规则服务、行情处理、Redis 索引、状态机、Outbox、RocketMQ 和通知查询。

## 工程边界

- JWT 使用 `localStorage` 是演示环境取舍，不宣称是所有生产系统的最佳方案。
- 页面只读取真实 API，不提供 Mock 数据模式。
- 当前不做复杂 K 线、真实证券行情、多渠道推送和后台管理大屏。
- AI 自然语言规则草稿属于 Phase 6B，不与基础页面一起假装完成。
