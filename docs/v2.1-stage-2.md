## 状态、去重与名额

个人订阅仍是持久期望；全局目标按股票唯一，预算行锁保证不同股票并发申请也不会超额。没有规则的个人需求同样进入上游集合；多个用户只产生一条全局订阅。

`version` 用于数据库观察更新，新增 `intent_version` 只在新的全局需求、失败重试或最终取消时推进。新增第二个正常用户引用不会变更全局意图，也不会重复发送订阅。连接 UUID、已确认集合和意图版本必须同时匹配，才能显示 CONFIRMED 并允许创建／恢复正式规则。

| 情形 | 行为 |
| --- | --- |
| 添加已验证资产 | 事务预留全局名额并保存个人需求，先返回 PENDING；提交后由协调器应用，不在行锁内发送网络请求 |
| 收到匹配的完整 ACK | 确认当前意图，显示监控中；只对实际已确认且仍被需要的股票转发行情 |
| 一个用户取消，仍有其他需求 | 同事务软删除本人的全部未删除规则，保留其他用户、触发和通知；不退订上游 |
| 最后用户取消 | 本人立即退出列表，规则同事务停用；全局保留名额，直到实际退订确认或新连接证明该股票不存在 |
| 取消时旧 subscribe 正在等待 ACK | 保留名额；旧 ACK 到达后补发 unsubscribe，不能确认已取消请求 |
| 取消后立即重加 | 新意图不能继承旧版本 ACK；必要时先退订旧意图，再订阅新意图，期间显示 PENDING |
| 405 明确额度拒绝 | 按供应商明确的“原集合不变”语义，只将新增股票标为失败；已确认股票继续工作，失败股票不盲目自动重试 |
| 400／410／500 的新增订阅错误 | 保存失败并保留不确定名额，重建同一接入连接，沿用缺口／基线策略；新连接证明未订阅后才释放，避免失败股票引发无限重连 |
| ACK 超时、断线或重启 | 不沿用持久 CONFIRMED；根据数据库需求恢复，旧连接回调无效，恢复首笔仍只建基线 |

协议依据：[Alpaca WebSocket Stream](https://docs.alpaca.markets/us/docs/streaming-market-data)。本轮仅在合成协议和 localhost JDK WebSocket 中验证实现，**未将这些结果标成实际账户订退订／超限验收通过**。

协调器读取需求与应用的过程串行化，旧数据库快照不能在新快照之后覆盖网络期望。命令没有服务端请求 ID，因此同时只保留一个变更；重复旧 ACK 不能结算新命令，异常集合触发恢复。新订阅或同股新意图建立新通道／基线，无关股票保留原通道、顺序和连续性。动态 ACK 不重置连接的健康时长，避免频繁增删影响重连退避恢复。

## 原十五股与跨阶段兼容

三个公开默认开关均为 false：

```yaml
price-pulse:
  monitoring:
    enabled: false
    dynamic-subscriptions-enabled: false
    adopt-legacy-holds: false
```

静态模式继续使用原配置十五股。动态模式首次加载从 V9 的持久需求和兼容持有开始，不因页面取消或默认列表调整丢掉原接入。只有明确启用兼容接管、该股当前意图已获实际确认、且不存在缺少个人订阅的 ACTIVE／COOLDOWN 规则时，才撤销 `legacy_hold`。有用户需求时接管不改变上游集合；需求为零时再等待正常退订确认。孤立的生效规则会阻止接管，不静默失去行情。

当前安全预算仍为 **15**。已经观察过十五股同时确认，但没有在当前账户验证更高上限；没有提升到 30，也没有执行超限探针。取消后的名额可能还在等待上游确认，错误提示会明确说明，不能把“事务已取消”当作“上游名额已释放”。

正在运行的 V8 后端及原 Vite 代理的新能力接口仍返回 404，前端继续阶段 1 已验证的明确兼容显示，不提供假的新管理入口。
