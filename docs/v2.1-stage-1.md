## 已实施

用户只有“股票监控列表”，搜索添加即请求监控，不再维护收藏／实时两个用户开关。无规则仍保存该股票的行情需求。界面严格区分 PENDING／订阅中、CONFIRMED／监控中、FAILED／接入失败；确认来自当前连接实际 ACK 的股票集合，不能沿用旧连接的持久确认。

- V9 新增 `alpaca_assets`、`user_stock_subscriptions`、`market_subscription_targets`、`market_subscription_control`，扩展共享 `stocks` 名称和资产 ID。一次性给现有用户建立原十五股需求，不改价格、规则和历史；新用户初始为空，取消后不在登录或重启时补回。
- `monitoring/AlpacaAssetClient`、`AssetCatalogService/Writer` 访问并缓存 Alpaca 股票资产目录，支持代码／名称、资产 ID 校验、停用状态、长名称和失败缓存。搜索不限本地十五股；供应商当前股票与 ETF 类别均可为 `us_equity`，不猜测分类。
- `MonitoringService/Mapper/Controller/Models` 提供本人列表、批量最近有效价、名额、添加／重试、取消预览及确认。历史缓存价仅用于展示，未伪装成真实逐笔接受价，不写业务水位。
- 取消先明确提示所有未删除规则均将停用并逻辑删除，包括 PAUSED／COMPLETED。确认携带个人版本和完整规则集合摘要；同一 MySQL 事务取消本人需求、删除本人规则并更新既有 Redis 索引 token。并发规则变动返回冲突，要求重新确认；历史触发／Outbox／通知和其他用户规则保留。
- `MonitoringAccess` 在现有 `AlertRuleService` 创建、恢复和生效规则编辑入口校验本人订阅确认。暂时掉线不会自动改动已有规则状态，页面分别显示“已启用”和行情订阅状态。
- `MonitoringHistoryService` 显式准备历史缓存，按股票合并任务，限制工作线程／队列并复用覆盖范围。时间线 GET 继续只读，未调用真实行情处理器。
- `StockMonitoringPanel.vue`、`utils/monitoring.ts`、前端 API／类型和 `DashboardView.vue` 接入统一列表、目录防抖、重复／失败反馈、明确取消确认、批量报价及账户切换响应隔离。保留原图表、时间轴、规则表与触发事件。

## 跨阶段兼容

阶段 1 的 `LegacySubscriptionTransport` 只观察现有静态连接，**不能发送动态订阅或退订**。原十五股用 `legacy_hold` 保持全局名额和接入，个人取消仅终止本人的规则需求，不会中断其他用户或现有正式流。默认安全上限仍为 15，当前账号超过十五股的能力没有验证。

非现有接入股票可搜索，界面明确显示“暂不可接入”并禁用申请，不能出现添加成功却被误认为监控中。后端也不会假确认：容量不足明确拒绝；静态适配器无法处理且有容量的直接请求记录失败，释放该非兼容名额并保留失败原因。支持任意新股票的动态接入属于阶段 2，尚未交付。

新管理接口默认关闭：`price-pulse.monitoring.enabled=false`。新前端检测正在运行的旧 V8 后端缺少能力接口时，显示“当前显示原有共享监控，个人监控管理尚未启用”，沿用旧行情列表，不开放添加／取消管理。普通网络错误不会冒充这种兼容回退。

管理开关不阻止 Flyway。新后端启动会发现 V9，因此没有通过重启原服务来“试一下”。正式加载需要另行确认并执行下述迁移计划。
