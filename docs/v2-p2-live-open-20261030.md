## BA／ORCL 原因与修复准备记录

通过三个只读 Alpaca REST 请求查看两股最新 IEX 成交及 A／C tape 条件码映射，未建立第二条 WebSocket：两股均返回 `z=A`、`c=[" "]`。Alpaca 的 [Market Data FAQ](https://docs.alpaca.markets/us/docs/market-data-faq) 及条件码接口说明 CTA A/B 的普通成交用一个字面空格，Nasdaq 普通成交用 `@`。现有运行版本只接受 `@`／`F`，错误排除了两股的普通成交。

已在 `AlpacaProtocol.java` 准备最小修复：仅对 tape A/B 接受字面空格；每个附加条件仍须满足原保守过滤策略。零股、盘前盘后、均价、未知条件等不因此放行，未将空白字符串当作任意匹配，也未改变价格、事件身份或时间。真实历史、规则匹配、状态机、Outbox、通知及模拟逻辑均未改动。

新增 `AlpacaProtocolTest` 共 10 个用例，使用本次 BA／ORCL 实际返回样本验证正常成交、精确价格及纳秒时间，并覆盖 CTA 两种 tape、F 组合、排除条件、非 CTA 空格拒绝及 Nasdaq 原行为。修复前复现 3 项失败；修复后全部 94 项后端单元／契约／回环测试通过。首次完整回归的 3 项回环错误来自沙箱禁止本地 socket，获准后按原测试重跑通过，原失败日志保留。没有运行生产 IEX 探针或压力／故障测试；无前端变更，本轮不重复既有前端检查。
