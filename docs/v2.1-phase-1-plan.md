# PricePulse V2.1：阶段 1 最小实施方案

**已被用户修订替代：采用统一的个人股票监控订阅，不再实施本文件中的收藏模型及“有规则阻止移除”流程。当前实施依据为 [统一监控方案](v2.1-monitoring-plan.md)。本文件仅保留原审查记录。**

日期：2026-10-30，Australia/Sydney。状态：**完成代码、结构及只读供应商审查；尚未实施业务代码、迁移或加载。**本轮只交付方案，阶段 2 动态订阅和阶段 3 模拟跳空不在本轮实施。

## 1. 已核实的现状

- 本地代码为 `5f645a1`，数据库最新 Flyway 为 V8：15 个 ACTIVE 美股、37 条规则；当前没有资产目录缓存、自选或监控需求表。
- `stocks` 是共享业务股票目录，唯一键为 `(market,symbol)`；`StockService/StockMapper` 的搜索仅查询这张表，不能搜索目录外资产。`GET /api/stocks/**` 当前可匿名访问，不能把个人自选数据放进其响应。
- `DashboardView` 读取共享股票列表，再在浏览器过滤；未选中股票的价格通过多次 1D 时间线请求补齐，尚无自选批量价格接口。
- `RealMarketRuntime` 仅在启动时根据配置创建股票映射和行情队列，`AlpacaStream` 只接受与配置完全一致的订阅确认。它尚不支持动态增减股票。
- `MarketUniverse` 同时承担默认十五股、订阅硬上限和模拟起点白名单；搜索／历史／模拟资格需要与上游订阅容量分离，不能简单把 15 改为 30。
- `MarketTimelineService` 的 GET 是只读事务，不拉取远端，不执行规则；历史缓存目前只由固定十五股的后台同步准备。
- `AlertRuleService.create/resume/update` 只检查股票存在及规则状态，没有检查监控需求。新增共享股票后若不补保护，可能创建一直收不到行情的 ACTIVE 规则。
- `MarketFeedHealth.connection` 是全局连接状态。新增未订阅股票不能直接继承其 SUBSCRIBED 并显示为“监控中”。

只读供应商核对：现有账户 GET `/v2/assets?asset_class=us_equity&status=active` 返回 HTTP 200、14,342 个资产；PLTR 和 SPY 均 active、class=us_equity。250 个名称超过 128 字符，最长 229。当前原 IDEA 后端 81042／18081、Vite 21134／5173 保持运行，未停机、未写库、未建立 WebSocket，也未验证超过十五股的订阅权限。原始证据保留在忽略目录 `target/v21-stage1-review-20261030/`，不上传。

## 2. 三种概念独立建模

| 概念 | 数据来源／持久化 | 行为 |
| --- | --- | --- |
| 可搜索资产 | 后端同步的 Alpaca 资产目录缓存 | 代码／名称搜索、资产身份和状态校验；不自动创建所有业务股票 |
| 个人自选 | 用户与业务股票的关系表 | 添加、移除、重新登录恢复；收藏本身不申请实时名额 |
| 实时监控需求 | 阶段 2 单独持久化；阶段 1 保留当前固定配置 | 由用户显式需求及 ACTIVE／COOLDOWN 规则需求共同决定，全球按股票去重 |

资产可搜索、用户已收藏、供应商已确认订阅，是三个不同状态。价格来源也独立标记为已接受真实成交／闭合历史分钟／无数据；历史价格存在不代表已启用正式监控。

## 3. 阶段 1 的数据库增量

计划新增 **V9**，实际编码前再次核对迁移版本。SQL 中不请求供应商、不修改旧迁移。

| 对象 | 最小变化 |
| --- | --- |
| 新增 `alpaca_assets` | 缓存 provider asset ID、symbol、name、asset class、exchange、provider status、tradable、同步时间／版本；外部身份使用 asset ID，名称支持至少 512 字符 |
| 新增 `user_watchlist` | `user_id`、`stock_id`、`created_at`，唯一键 `(user_id,stock_id)`，按用户查询；删除仅删除本人关系 |
| 扩展 `stocks` | 加可空、唯一的 `alpaca_asset_id`，名称从 VARCHAR(128) 加宽至 VARCHAR(512)；保留原股票 ID、最新价、水位、索引 token 和历史引用 |
| 默认自选 | 一次性为现有用户加入原十五股；新用户在注册事务中初始化一次。登录、启动、目录刷新均不再次补齐，用户清空列表后保持为空 |

全量资产只进入目录缓存；用户真正添加时才复用或创建 `stocks` 记录。新股票的 `latest_price/latest_quote_at` 为空，不使用目录样例价。已有同代码股票复用原 ID；不同 asset ID 不能悄悄覆盖同代码旧股票的历史身份。

目录同步完整接收并验证响应后再发布新缓存；失败保留上一份缓存和明确的陈旧／失败状态，不能将一次网络失败解释为全部资产停用。目录元数据刷新不自动改正式规则状态、价格或现有订阅。

## 4. 阶段 1 接口与类

以下新接口均认证，用户身份取 JWT，不接受客户端 userId。

| 接口 | 职责 |
| --- | --- |
| `GET /api/assets?query=...&limit=...` | 搜索 Alpaca 目录缓存，按代码精确／前缀及名称匹配；返回 asset ID、代码、名称、真实资产类型、状态、是否本人已收藏及缓存状态 |
| `GET /api/watchlist` | 一次返回本人自选、批量最近有效价格／时间／来源及逐股监控状态，不再逐股下载整条时间线补列表价格 |
| `POST /api/watchlist`，body 为 `assetId` | 后端再次校验资产身份／状态，短事务复用或创建股票并插入本人关系；重复返回明确的 409，数据库唯一键处理并发重复 |
| `DELETE /api/watchlist/{stockId}` | 校验本人关系及生效规则，安全删除本人自选；不删除共享股票、历史、规则或其他用户数据 |
| `POST /api/market/stocks/{stockId}/history-requests` | 为有访问资格的股票显式准备缺少的历史缓存，返回任务状态；合并相同股票请求并限流 |
| `GET /api/history-requests/{requestId}` | 读取调用者有权查看的任务进度／安全错误，不暴露其他用户信息 |
| 保留 `GET /api/market/stocks/{stockId}/timeline` 及 events | 继续只读查询缓存、水位和本人事件；GET 不触发远端拉取或正式处理 |

`AlpacaAssetClient/CatalogService`、`WatchlistController/Service/Mapper`、`HistoryPreparationService`、逐股 `MonitoringStatusResolver` 属于新增薄层。`StockMapper/Service` 补资产映射和仅更新目录元数据的写法；`AuthService.register` 补一次初始化。`SecurityConfiguration` 保留旧公开目录接口的兼容性，但新个人接口不能被 `/api/stocks/**` 匿名规则覆盖。

Alpaca 的资产列表接口没有通用名称搜索参数，因此后端同步目录后再搜索，不把每个输入字符转发为供应商请求。前端防抖约 300ms，取消旧请求并丢弃迟到结果，区别空结果、目录不可用、资产停用、已添加。当前接口将股票与 ETF 都归类为 `us_equity`；阶段 1 展示“美股／ETF · us_equity”等真实分类。若需严格区分 STOCK 与 ETF，必须另有可信分类来源，不能用名称猜测。`tradable` 是交易能力字段，不是 IEX 数据权限或订阅上限证明。

## 5. 历史与批量价格

- 复用 `AlpacaDataClient`、`MarketHistoryCache`、已有分钟表／覆盖表和真实交易日历。目录刷新与历史准备采用独立有界执行器，不占用现有 WS 处理线程，不为所有可搜索资产下载历史。
- 优先直接返回已有缓存。新添加或用户请求的窗口未覆盖时，通过显式 POST 准备；任务只写历史缓存／日历／覆盖信息，不调用 ingestion、规则匹配、Outbox 或 MQ。
- 为最小复用现有“单连续覆盖范围”结构，每只按需准备股票使用原有受限滚动范围（最近一个月加缓冲，最多 45 天），覆盖 1H／1D／1W／1M。相同股票任务合并、限制并发并设置重试间隔，不盲目合并不连续的 coverage。
- 第一版任务队列可在进程内有界运行；完成结果已持久化，重启后根据 coverage 再请求即可，不宣称任务本身可恢复。无需新增消息中间件或通用任务平台。
- 列表价格用批量查询比较已接受 REAL 水位与已闭合分钟的真实时间，返回最近有效值及来源。历史分钟只用于展示，不能回填 `stocks.latest_price` 或触发提醒；两者都没有则明确无数据。
- 继续保留 dataQuality、缺失分钟、断轴和原始时间戳；完整下载范围不等于每一分钟都有 K 线，不补造稀疏 IEX 数据。

## 6. 阶段 1 必须具备的规则保护

1. 移除本人自选时若本人还有 ACTIVE／COOLDOWN 规则，返回明确冲突及规则数量，引导用户自行暂停／删除；不隐式暂停或删除。其他用户的规则不会因本人的自选操作被改变。
2. 移除检查与规则启用遵守现有同股票事务锁顺序，防止“检查后另一请求启用规则”的竞态。
3. 新增未监控股票只能查看历史；阶段 1 在 `AlertRuleService.create/resume/update` 补监控资格校验，拒绝在无监控需求的目标股票上新建／恢复／移动为有效规则，返回 `MONITORING_REQUIRED`。不在后台自动把旧规则改成 PAUSED。
4. 资格根据持久的预期监控范围判断，不能因短暂断线把所有旧规则改状态或拒绝所有正常编辑。阶段 1 的预期范围仍是原配置十五股；阶段 2 替换为需求服务。
5. UI 区分规则逻辑 ACTIVE 与实际监控状态。逐股确认订阅且正式处理启用才显示“监控中”；重连显示“订阅中／恢复中”，失败显示“行情不可用”，新增目录外股票显示“未监控”。阶段 1 不提供尚未实现的启停开关。

这是个人自选上线时必要的兼容保护；Redis Lua、阈值索引、状态机和正式通知语义保持原样。现有十五股不因收藏列表改变而取消订阅。

## 7. 阶段 2 的衔接边界（本轮不实现）

- 新增独立的持久化用户监控需求，收藏关系不包含决定上游订阅的布尔开关；有效规则是不可被收藏删除抹掉的需求来源。
- 全局目标为各用户显式监控需求与 ACTIVE／COOLDOWN 规则需求的去重并集。创建／启用／迁移规则与名额预留在 MySQL 事务内协调，超限直接失败；不在事务内等待 WebSocket 网络 I/O。
- 引入轻量共享订阅协调器，对当前唯一 WS 发送增量变更并等待供应商实际确认。重启／重连从持久需求恢复；被移除后重新加入的股票必须有新的接收连续性，首笔重建基线；无关股票不因别人的变更被重新建基线。
- 同一股票多人使用只占一份；仅在所有显式及规则需求消失后才可退订。取消监控遇本人有效规则时要求先显式处理规则，不能静默解除必要订阅。
- 原十五股需要在阶段 2 加载计划中明确迁移为可追踪的兼容监控需求及用户／规则归属，不能用“所有用户都收藏了它”推导监控，也不能切换时漏订。
- 官方 Basic 公开上限为 30，但当前程序只实现并验证十五股；本次资产查询不证明账户的 WS 上限。先保留 15 的受验证边界，阶段 2 再结合当前账户资料、受控确认与供应商 ACK 验证。未经授权不创建竞争连接、不用现有正式监控做超限探测。

## 8. 模拟开盘跳空的最小复用方向（阶段 3，本轮不实现）

- `RuleTransitionEngine.evaluate` 已是纯函数。将模拟参考价作为 previous、模拟开盘价作为 current，直接复用其方向及严格／包含边界；ONCE→COMPLETED、REPEAT→COOLDOWN、重新激活均沿用。
- `SimulationIsolationService.begin` 已冻结本人规则并将非 PAUSED 初始化为 ACTIVE；`advance` 已支持 1–60 个点、批次幂等和版本校验，并只写 `simulation_*` 与独立 Redis key。
- 开盘批次仅准备一个点，时间取冻结日历中下一有效 session 的 **open**。当前 `SimulationCalendar.minutes(close,1)` 会得到下一日开盘后一分钟，不能用它冒充开盘；需新增明确的 `nextSessionOpen` 辅助方法。随后继续原 60 个交易分钟推进和现有播放／暂停流程。
- 自定义参考价存为 SIMULATION 起点／上下文，不塞进 ALPACA 真实前缀，不调用 `QuoteIngestionService` 或真实 `OpeningGapPolicy`。真实来源记录原始历史点和实验时间的对应关系，保留真实时间与价格。
- 为模拟点／事件增加向后兼容的跳空上下文，保存参考价、开盘价和模拟时刻；现有旧实验仍能恢复与继续，不因新增场景使旧生成器版本全部失效。
- 复用统一 `PriceSparkline`、`timeAxis`、规则表、事件表与定位逻辑；只补模拟跳空标记和按需详情。真实供应商可信参考／连接代次资格继续由现有正式专项测试验证。

`SimulationOriginResolver` 目前也含十五股白名单。阶段 1 将新增股票的普通模拟资格改为已验证资产映射，兼容原十五股，保留真实起点、覆盖、修订和日历校验；不提前加入跳空模式，不将“已收藏”当作“已订阅”。`MarketUniverse` 的原名单保留为默认自选／现有接入的兼容范围，不再充当完整可搜索资产池；订阅硬边界仍留在阶段 2 单独处理。

## 10. 阶段 1 验收、迁移与暂停点

- 单元／模拟 HTTP：目录外 PLTR、代码与名称匹配、SPY 类型如实展示、250 类长名称兼容、未知／停用／失败反馈、目录刷新失败不覆盖可用快照。
- 临时 MySQL：V8→V9 与干净库迁移；原规则／真实报价／触发／Outbox／通知事实保持；同用户重复／并发重复受唯一键约束，不同账户的添加／移除独立；清空后重启／重新登录不重新加回。
- 历史与报价：首个目录外自选股显式准备后可读四窗口；GET 前后业务与缓存均无写入；批量有效价格／无数据／过期来源正确，不以历史价推进真实水位。
- 一致性：本人有效规则阻止移除，其他用户不受影响；新增未监控股的创建／恢复／移动保护在后端生效；临时断线显示恢复中，未订阅股票不冒充监控中。
- 前端：防抖、快速搜索迟到响应、重复添加、空列表、移除当前股票、登录切换隔离；普通模拟已保存实验不因自选变化被删除。运行相关前端测试、类型检查与构建。
- 不为验收在正式库创建测试账户／规则，不并开 IEX；供应商资产查询成功只说明目录可读，不记作新股票监控已通过。

实际库加载前先备份并核对 V8 指纹，先在隔离库验证 V9 的 DDL 耗时／锁及迁移兼容。应用回退保留新增表、列和用户数据，不执行 DROP 或整库恢复覆盖后来真实触发；应回到保留新股票监控保护的兼容构建。旧 V2 会全局列出新共享股票，直接回到旧二进制并不具备完整行为兼容性，回退演练必须覆盖这一点。正式加载仍需单独协调当前接入，不自动重启或执行线上迁移。

本轮不运行实现验收，因为尚未编码。阶段 1 方案交付后暂停；下一步仅实施搜索、自选及其必要兼容保护，完成后汇报文件、测试和遗留，再等待阶段 2。IEX 主动关闭 1006 和真实跨日开盘待验继续保留。
