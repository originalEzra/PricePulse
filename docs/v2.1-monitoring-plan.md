# V2.1 统一股票监控订阅方案

2026-10-30。用户最新修订取代原“收藏／监控分离”产品方案。阶段 1–3 已交付，[阶段 4 整体隔离回归](v2.1-stage-4.md) 已完成；随后用户正式批准按 [加载计划](v2.1-rollout-plan.md) 升级 V10，现已加载并确认原十五股，详见 [最终交付](v2.1-final-delivery.md)。阶段 2／3 细节保留在 [动态订阅记录](v2.1-stage-2.md) 与 [模拟跳空记录](v2.1-stage-3.md)。下文阶段 1 的未加载／静态兼容描述保留为设计历史，最终运行采用阶段 2 动态协调器。

## 产品与数据

- 用户只有“股票监控列表”：搜索添加就是请求监控，无规则也有行情需求，不提供收藏状态或独立实时开关。
- `user_stock_subscriptions` 持久化本人期望、版本及取消时间；同用户／股票唯一。取消保留记录，重新请求不复活已删除规则。
- `market_subscription_targets` 按股票唯一，保存全局名额预留、PENDING／CONFIRMED／FAILED／CANCELLED、请求版本、确认连接标识、安全错误及兼容持有标记。多用户引用通过有效个人订阅计数派生，避免独立计数漂移。
- `market_subscription_control` 单行锁串行化不同股票的名额申请，默认安全上限 15。公开 Basic 30 股不等于当前账户已验证 30；阶段 2 另核定。
- `alpaca_assets` 缓存外部资产目录；全量资产不自动导入业务股票。股票名称加宽至 512 字符，增加可空 Alpaca asset ID，保持原 ID、价格、历史。

V9 仅追加结构、一次为现有用户建立原十五股个人需求，并将原十五股作为兼容持有目标。迁移状态为 PENDING，绝不伪造供应商确认；新注册用户初始为空，不在启动／登录时补回已取消项目。

阶段 2 的 V10 仅追加全局 `intent_version`，与观察更新的 `version` 分开，用于取消／重加和失败重试的异步确认隔离。V9 没有修改，正式库仍未运行 V9／V10。

## 状态与跨阶段兼容

1. 添加先验证资产，再在股票锁和全局预算锁下去重、预留唯一股票名额，提交期望；不在 MySQL 事务中调用 WebSocket。
2. 只有当前连接实际确认覆盖该股票且业务处理已启用，界面才显示 CONFIRMED／监控中。持久确认的旧连接标识不能跨重启直接使用；掉线时显示 PENDING／恢复中，拒绝时显示 FAILED。
3. 阶段 1 的适配器只能识别现有固定订阅确认，不支持向连接增加／减少股票。其余股票显示接入暂不可用，不能返回假确认。容量已满时明确拒绝；静态适配器不能处理的请求记录失败并释放非兼容预留，留存用户可见原因。
4. 原十五股兼容持有不随个人取消而退订，因此当前正式接入保持；阶段 2 在明确加载计划下由持久化个人需求接管兼容持有，才允许最后用户取消后的全局退订。
5. 新前端若连接尚未升级的 V8 服务，检测新能力接口缺失，继续旧只读列表／行情，不开放新管理动作，不显示添加成功。
6. 阶段 2 新增协调器，持续对比数据库期望与当前连接实际订阅，幂等发送差量并等待 ACK；先持久期望后网络、确认前崩溃、网络后崩溃、超时／拒绝、取消后重加均以请求版本和连接代次恢复。新加入股票建立新基线，无关股票连续性不变。

阶段 2 的名额还必须覆盖“上游结果未知”：订阅请求已发但 ACK 超时，或最后一个用户取消后退订尚未确认时，不能立即释放名额。只有明确拒绝且未订阅、实际退订确认，或连接已关闭且新连接完成集合重建，才能回收。对同一连接串行协调差量，用 ACK 中实际股票集合与当前期望核对；旧代次／旧版本的迟到 ACK 不能使已取消请求重新变为监控中。用户取消的 MySQL 事务先完成，后续网络退订失败不会复活其规则。

## 取消事务与规则

- 先读取取消预览，明确提示该股票所有未删除提醒会同时停用并逻辑删除，历史触发和通知保留。
- 确认请求包含个人订阅版本与规则集合摘要。事务内锁股票、预算及本人订阅，再校验规则集合；并发新增／编辑导致摘要变化时要求重新确认。
- 同事务取消本人期望，逐条复用规则软删除和 Redis 索引 token 更新；失败整体回滚。ACTIVE／COOLDOWN／PAUSED／COMPLETED 均转 DELETED，保留触发和通知原行，不改其他用户。
- 规则创建／恢复和有效规则移动，仅允许本人当前已确认监控的目标股票。已有规则遇临时断线不自动改状态，页面区分规则已启用与行情未确认。

## 阶段 1 接口与实现

- `GET /api/assets`：目录代码／名称搜索、真实资产类型、停用／失败信息；缓存目录，前端防抖及迟到响应保护。
- `GET /api/monitoring/capabilities`：是否启用个人管理、是否支持动态订阅、受限容量。
- `GET/POST /api/monitoring/subscriptions`：本人列表及批量有效价格／来源；添加监控请求。
- `GET /api/monitoring/subscriptions/{stockId}/cancellation`：取消版本、规则数量和摘要。
- `POST /api/monitoring/subscriptions/{stockId}/cancel`：显式确认后的原子取消。
- `POST /api/monitoring/subscriptions/{stockId}/retry`：失败请求重试，重新检查预算和连接事实。
- 显式历史准备请求与只读任务状态；原时间线 GET 保持只读，缓存价不进入真实接受水位。

新接口全部 JWT 身份隔离。管理功能默认关闭，隔离测试显式开启；部署前先验证 V9、兼容持有和回退，再单独确认加载。阶段 1 不改变现有 WS 数量／订阅集、不探测超限、不改生产规则。

注意：管理开关不是 Flyway 迁移开关。新构建启动时仍会发现 V9，因此不能在未获正式加载授权时重启原 IDEA 后端。当前前端直接兼容正在运行的 V8 服务；阶段 1 代码与正式加载分开交付。

## 改动位置与复用边界

| 范围 | 最小增量／直接复用 |
| --- | --- |
| 数据库 | V9 新增四张表并扩展 `stocks`；不改真实价格、触发、Outbox、通知或模拟事实表 |
| 资产搜索 | 新增 `AlpacaAssetClient`、`AssetCatalogService/Writer`；仅后端持有凭据，缓存真实目录，资产 ID 再校验，不用固定十五股充当搜索池 |
| 个人订阅 | 新增 `MonitoringService/Mapper/Controller`、`MonitoringModels`；统一个人期望、全局去重名额、版本与取消预览 |
| 上游事实 | 阶段 1 新增只观察现有连接的 `LegacySubscriptionTransport` 和协调观察器；`MarketFeedHealth/AlpacaStream` 记录实际 ACK 股票集合，不发送新差量命令 |
| 规则一致性 | 复用 `AlertRuleMapper` 逻辑删除、股票行锁、`RuleIndex.changed`；仅在 `AlertRuleService` 增加当前订阅确认资格校验 |
| 历史行情 | 复用 `AlpacaDataClient`、`MarketHistoryCache`、时间线 GET；新增有界且按股票合并的显式缓存准备任务，批量展示最近有效价，不写真实行情水位 |
| 前端 | 新增 `StockMonitoringPanel` 和防抖工具，接入原 `DashboardView`；保留原图表、交易时间轴、规则表和触发详情 |
| 正式规则／通知 | 直接复用 Redis ZSet + Lua、`RuleTransitionEngine`、MySQL 事务、Outbox、RocketMQ、消费幂等；本轮不更换语义 |

Alpaca 的股票及 ETF 资产在当前接口均可能返回 `us_equity`；界面显示供应商实际资产类别，不从公司名称推断 ETF 分类。上游额度仍只确认过现有十五股，不把公开套餐上限当作当前账户能力。

## 后续阶段

阶段 2 已实现同一连接的动态差量订阅、ACK／失败／重连协调与兼容接管，并在隔离环境验证多用户去重和最后引用退出；不是新增另一套用户模型。默认仍关闭，未加载到正式服务；真实供应商验收没有用合成结果替代。阶段 3 已复用纯 `RuleTransitionEngine` 和 `SimulationIsolationService`，以冻结日历下一 session.open 的一个离散点模拟跳空，真实历史与自定义 SIMULATION 参考均已验证，保留实验幂等及真实链路隔离。阶段 4 已完成整体回归、真实临时 Broker、长实验、进程恢复与备份／迁移演练；交付计划后暂停，尚未执行正式加载。

模拟跳空仍按已有实验开始时冻结规则配置：未暂停规则在实验中从 ACTIVE 开始，PAUSED 不参与，使用相同 ABOVE／BELOW 边界、ONCE／REPEAT、COOLDOWN／再激活判定。新场景只新增实验输入、下一有效交易日开盘点、参考价与模拟事件上下文；自定义值标为 SIMULATION，不伪造供应商连接或调用 REAL 行情处理器／生产 Outbox 发布器。真实开盘参考价可信度、连接代次和恢复基线继续由正式链路的隔离集成测试覆盖，不能用模拟界面替代供应商验收。

## 验证与回退

阶段 1 在临时 MySQL／Redis 验证 V8→V9、重复及并发预算、两个用户共享、取消事务回滚、规则摘要竞态、旧历史保留、旧连接确认失效、失败无假监控、目录外资产／长名、只读历史、前端防抖与 V8 回退显示。相关单元、集成、前端类型／构建通过后汇报并暂停。

回退保留新增表和用户请求，不 DROP、不用整库恢复覆盖新的正式通知；保留必要的监控资格保护。正式迁移／重启／修改当前规则均不包含在阶段 1 授权内。IEX 1006 及自然跨日待验继续保留。
