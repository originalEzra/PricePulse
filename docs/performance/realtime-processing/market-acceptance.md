# 自然市场补充验收清单（尚未执行）

离线队列实验、回环 WebSocket 测试与自然 Alpaca IEX 成交是三种证据。周末的合成数据不计作自然市场 PASS。当前正式进程保持原代码，不能假定已加载新的观测钩子或优化。

## 加载前

- 先取得受控加载许可；本轮不得重启原后端、迁移正式库或并开真实 IEX。
- 核对十五股实际确认状态、正式写入开关和连接代次，记录现有 IEX 1006 等遗留。
- 仅采用低开销的内存聚合指标，不逐笔同步日志；限制股票标签数量，禁止用户／事件 ID 作为监控标签。
- 本轮各阶段精细 SQL 计时器在测试 classpath。自然验收若需同等细分，须先将经过验证的观测适配到正式运行配置；不能声称现在的原进程已有这些指标。
- 队列／处理／提交边界已有默认关闭的[运行时适配器](runtime-metrics.md)；受控加载时单独决定启用。没有更改现有 Actuator 暴露或安全策略。

## 正常交易时段

- 用供应商交易日历确认时段，分清事件时间、接收时间、入队／开始时间、真正提交返回和通知落库时间。
- 以接收侧计数记录每股实际输入峰值；已持久化报价数量不能代替输入量，尤其不能忽略舍弃任务。
- 连续观察输入／完成速率、每股队列深度、最老等待、P95／P99、溢出与实际舍弃；注明样本数、观测时长和 JVM／数据库共享负载。
- 观察重连、单股异常和首次恢复基线，不能为了造场景主动中断正式监控。
- 自然触发时关联触发、Outbox、Broker 和幂等通知；校核 JVM／MySQL 时钟后再计算跨组件延迟。不制造正式规则或成交。
- `quote_events.processed_at` 在事务体中赋值，不能拿它冒充提交完成时间。
- 若未自然出现开盘跳空或故障，保留“未发生／未验”；不补造样本。

## 独立产品项

- “达到目标价即提醒”会改变现有穿越语义，本轮未实施。
- “断线约 30 秒后正式异常通知”独立于行情提醒。当前回环测试验证心跳、单连接代次故障去重、客户端暂停和恢复；不能将它描述为已实现跨重试故障事件聚合或正式异常通知。
- 后续设计应按连接、订阅、队列区分故障，使用首次异常开始时间而非每次重试更新时间；以故障事件 ID 去重，恢复后闭合。无成交、正常休市不构成连接故障。正式通道实现与验收另行授权。

当前全部项目均为自然市场待验，不以离线成绩替代。
