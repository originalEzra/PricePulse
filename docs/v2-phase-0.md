### 连接关闭的已知现象

本机 Node 原生 WebSocket 在主动结束观察窗口后，收到 closeCode=1006。认证与订阅已经成功；重连也成功。本轮没有把它隐去或假写成干净关闭：

- 最初严格按非 1000 关闭码判失败的两次报告保留在 `provider-attempt-1.json / provider-attempt-2.json`。
- 探针改为区分“观察窗口结束后客户端主动关闭”和“观察中连接意外断开”。前者保留 `UNCLEAN_CLOSE_AFTER_PROBE_WINDOW` 警告，后者仍失败。
- 单元测试验证这两种情况不会混淆；认证失败、订阅超时、协议错误不能靠该兼容处理变成成功。
- P2 的 Java WS 客户端仍需验证关闭握手、心跳、意外断线和退避重连。P0 的 Node 探针不替代这一验收。

### 数据范围与费用边界

[Alpaca 官方说明](https://docs.alpaca.markets/us/docs/market-data-faq)区分 IEX 单交易所与 SIP 全市场数据。本轮仅访问 IEX；5 股订阅成功只证明本次需求范围可用，不代表测出了账号所有订阅／连接上限。[历史接口](https://docs.alpaca.markets/us/reference/stockbars)按 symbol 排序且要持续翻页；不能因为第一页主要只有一只股票就认定其他股票没有历史。

本轮范围是本机开发验证。未来公开多用户部署是否需要另外的数据授权，须核对账号接受的协议和供应商条件；P0 不以 API 返回 200 推断授权已完成。

## 5. 探针复现与密钥配置

已有 Node 运行时即可，无需增加 npm 依赖或修改 Java POM。

本机凭据文件为 `.local/alpaca.env`，已被 Git 忽略、权限 600；填入 Paper Trading API Key ID／Secret，不是登录密码。文件不在前端目录，报告不保存 Key、Secret、认证帧或上游原始错误正文。

```bash
# 在仓库根目录执行；先在本地编辑 .local/alpaca.env。
node --test scripts/tests/v2-market-data-probe.test.mjs
node --env-file=.local/alpaca.env scripts/v2-market-data-probe.mjs
```

只允许固定的行情／日历／时钟 HTTPS GET 端点和 IEX WS 的 auth／subscribe／close。脚本不导入 PricePulse 服务、不连接数据库／Redis／MQ、不访问交易订单接口，也不调用现有 `/api/market/quotes / simulate / replay`。

结果：

- 退出 0：本次技术探针检查通过；用途授权仍需另行核对。
- 退出 1：至少一项技术检查失败，查看安全的错误码。
- 退出 2：凭据缺失或样本不完整，不当作通过，也不自动跳过。

默认观察两次、每次 20 秒。`PRICEPULSE_PROBE_SECONDS` 可设为 5–60；正常交易时段建议 60 秒，仍只是有限样本，不能冒称覆盖完整峰值。
