# Phase 6B：AI 自然语言提醒草稿

## 目标

让用户用一句自然语言表达价格提醒需求，由模型整理成结构化草稿。AI 只降低表单填写成本，不负责投资判断，也不直接创建、修改或删除任何业务数据。

## 业务链路

```text
用户输入自然语言
    ↓
Spring AI + JSON Schema 提取候选字段
    ↓
后端解析价格、查询真实股票、校验规则关系
    ↓
信息不足：返回澄清问题
信息完整：返回结构化草稿
    ↓
Vue 展示草稿并填入普通规则表单
    ↓ 用户检查、修改并点击保存
原有提醒规则 API 执行最终校验和持久化
```

## 为什么不让模型直接创建规则

- 模型可能误解代码、价格、方向或重复提醒语义。
- 模型输出不是业务事实，不能替代数据库查询和服务端校验。
- 保存动作需要当前用户身份、数据权限和原有领域规则。
- 用户确认让错误在产生业务状态前可见、可修改。

因此 `/api/assistant/alert-drafts` 是只读接口。它返回草稿或澄清问题，不调用提醒规则写服务。

## 结构化输出与后端校验

模型输出包括：

- 是否已具备完整信息；
- 一个可选澄清问题；
- 股票代码及可选市场代码；
- 上破或下破；
- 触发价格；
- 单次或重复提醒；
- 重复提醒的重新激活价；
- 可选名称和备注。

价格先以字符串接收，随后交给 Java `BigDecimal` 和项目统一的 `PriceTicks` 校验，避免模型或 JSON 浮点表示决定金额精度。股票代码必须精确匹配数据库中的启用股票。重复提醒还要满足：

- 上破规则的重新激活价低于触发价；
- 下破规则的重新激活价高于触发价。

数据库允许不同市场出现相同股票代码。未提供市场且存在多个匹配时，接口要求用户补充市场代码；提供市场后按市场和代码共同解析，不任意选择一条记录。

模型调用期间不持有数据库事务或连接，只有解析完成后才查询股票，避免较慢的外部请求占用连接池。

## 澄清与失败策略

- 缺少股票、方向、阈值或重复提醒重新激活价：返回一个简短澄清问题。
- 股票不存在：返回 404，不让模型虚构股票。
- 模型超时、供应商异常或结构化输出无法转换：返回 503，用户仍可手动创建规则。
- API Key 不会写入配置文件或 Git。AI 默认关闭，只有显式启用时才校验配置并创建供应商客户端。
- 系统指令和用户需求使用独立的消息角色。解析失败只记录异常类型，不把原始输入、模型原文或密钥写入应用日志。

## 前端确认流程

行情页增加“AI 文本生成”入口：

1. 用户输入一句提醒描述。
2. 信息不足时在原弹窗展示澄清问题，用户补充后重新生成。
3. 信息完整时展示股票、方向、价格、模式和重新激活价。
4. 点击“填入规则表单”后进入原规则编辑弹窗。
5. 用户可以修改任何字段，最后点击“保存规则”才创建业务数据。

修改需求会立即清空旧草稿，关闭弹窗会取消未完成请求。即使模型返回的股票未包含在首屏股票列表中，页面也会按 ID 读取股票后再打开规则表单。价格预览保留四位小数。

## 验证

后端测试覆盖：

- JSON Schema 包含全部预期字段；
- 完整输出能够解析并规范化金额；
- 不完整输出直接返回澄清问题且不查询股票；
- 重复提醒缺少重新激活价时要求补充；
- 不存在的股票无法生成可保存草稿；
- 跨市场代码歧义、显式市场匹配和价格精度拒绝；
- OpenAI 兼容响应解析、消息角色、JSON Schema 请求、损坏输出和读取超时；
- 真实 MySQL 中的跨市场解析，以及 AI 接口的认证、请求校验和关闭时的 503。

本阶段结果：18 项单元/上下文测试和 17 项 MySQL/Redis 集成测试通过；前端类型检查、生产构建通过。浏览器使用临时的本地模型响应接口，验证了澄清、补充价格、草稿失效、填入表单、人工修改及最终保存，触发价 `110.1234` 正确保留。

浏览器测试使用合成账户，模型响应由测试接口提供。这证明前后端与模型适配器的功能链路，不代表已测出真实模型对自然语言的准确率。本阶段未产生云端模型调用。

验证命令：

```bash
./mvnw -B -ntp test
cd frontend
npm run type-check
npm run build
```

真实模型连通性仍可独立使用 `./mvnw -Pai-live verify` 验证。这样供应商可用性测试与业务功能测试互不绑死。
