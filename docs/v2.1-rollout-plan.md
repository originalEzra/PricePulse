## 加载范围与前提

- 沿用原 IDEA 配置、Alpaca 账户／IEX／环境和十五股，正式写入保留 true，正式 RocketMQ 不停机、不换 Topic／消费组语义。
- 一次协调停机内，依次执行 **V8 → V9 → V10**，再启动同一个正式后端。只有旧进程与旧接入连接退出后才能启动新实例，不能蓝绿并行连接同一个 Alpaca 账户。
- V9：扩展 `stocks.name`、追加可空资产 ID 和四张目录／订阅表，一次性为现有用户保留原十五股个人需求及全局兼容持有。V10：追加 `intent_version`。阶段 3 没有新迁移。
- 不修改旧 V1–V8 文件或历史 checksum，不清 Redis，不删除历史，不重新执行已处理行情或历史触发。
- 当前安全名额仍为 **15 个全局去重股票**；不将公开 Basic 30 股当作账户已验证额度。迁移本身不提高名额。
- 确认前需固定已验收构建和源码／SQL 指纹，包含所有必要未跟踪源码，保留现有未提交工作；私人配置、备份和 target 产物不进入 GitHub。准备同版本的静态兼容启动配置作为有限回退方案。

## 备份与维护窗口

建议选择美股正常时段之外，经用户明确确认后执行。维护前暂停本人在页面上的创建、取消和实验替换操作，避免人为变更与加载核对交错。

1. 原后端保持运行时做一份预备一致性备份，用于提前在独立临时 MySQL 检查恢复、Flyway 与原数据；临时验证不得启用 Alpaca、正式消息或业务写入。后续只读预检已完成一份实际正式 V8 备份的隔离恢复与 V9／V10 演练，验证通过；该预备备份有时点边界，仍不代替维护窗口内的最终截止点备份。若加载推迟或源数据改变，应按最新状态复核备份。
2. 在 `.local/backups/v21-before-v9-v10-<timestamp>/` 保存 SQL、清单和摘要，目录 700、文件 600。使用现有容器内部凭据，不输出密码／Key／完整 SQL，至少采用以下 mysqldump 选项：

   ```text
   --single-transaction --routines --events --triggers --hex-blob
   --set-gtid-purged=OFF --no-tablespaces
   ```

3. 记录 SHA-256、字节数和 dump 完成标记；核对 Flyway 历史、业务表、模拟表与历史缓存均在备份中。四份私人配置只记录指纹；原配置文件留在本机受保护位置，不改写或打印。
4. 进入最终维护窗口后，协调停止原 IDEA 后端，确认 18081 端口释放、旧进程退出，记录实际停止与最后接受行情时间。原 Vite 5173 可保持，但此时 API 暂时不可用。
5. 后端完全退出后，再做**最终截止点备份与只读数据清单**；以此为本次迁移的恢复点，不用较早预备备份覆盖维护前的新通知。

预留 **5–10 分钟维护窗口**，不是保证中断时长。实际后端中断包含退出、最终备份、DDL、启动和 IEX ACK；正式备份体积、元数据锁或供应商重连会延长窗口。临时小夹具迁移耗时不能外推正式库。

停机期间不接收／判断新成交；原已提交 Outbox 和 Broker 事实保留，后端恢复后继续投递。内存中尚未接受的尾段不保证保留，恢复第一笔只建立基线，**不补发维护窗口内的穿越提醒，也不追补今日开盘**。不能把本次加载称作零停机或零漏报切换。

## 迁移与启动顺序

1. 将最终快照与预期清单比对。当前基线为 37 条规则、17 条触发／Outbox／通知、131178 REAL、961 LEGACY、15 水位、模拟 1 个／6 批次／2 事件；加载发生在以后时须重新采集，正常新增事实不可当作错误回滚。
2. 在旧进程已退出的条件下，用一次性 Flyway 迁移过程仅对既定本机库依次执行 target V9、target V10；该过程不启动 Spring 运行时、IEX 或消息投递，连接凭据只在内存读取。沿用现有 Flyway locations，包括已应用的 `db/local` 重复迁移；本轮正式库确有 1 个 repeatable 记录，不能遗漏其路径或改变 checksum。完成静态数据核对后再启动正式后端，其 Flyway 应只校验、不重复执行。直接启动新构建也会发现迁移，管理开关不是迁移开关，不能把未经备份的直接重启当成迁移准备。
3. 检查成功迁移各一次、最终版本 V10、checksum／validate 成功。V9 应生成 15 个全局目标、每个现有用户 15 条个人需求；本轮只读核对为 3 个现有用户，预期共 45 条，实际加载时按最新用户数重算。初始 PENDING、兼容持有与预留均为 true，confirmed_epoch 为空；V10 的初始 intent_version 为 0。不得手工把状态写成 CONFIRMED。
4. 在接入开始前核对所有旧规则定义／状态／版本／生效时间、股票 ID、触发快照、Outbox／通知及已保存模拟数据保持。新订阅表的增加、`stocks` 新列和名称宽度是预期差异，不能要求整库二进制校验和不变。
5. 拟加载的三个功能开关如下，实际修改私人启动配置也包含在后续加载授权内，本轮未修改：

   ```text
   PRICEPULSE_MONITORING_ENABLED=true
   PRICEPULSE_DYNAMIC_SUBSCRIPTIONS_ENABLED=true
   PRICEPULSE_ADOPT_LEGACY_HOLDS=true
   ```

   保持原 `PRICEPULSE_ALPACA_BUSINESS_WRITES_ENABLED=true` 和其余凭据／IEX 设置。初始上游集合仍是原十五股，预算不提高。
6. 新进程只建立原账户的一条 WebSocket。以当前连接完整 ACK、当前意图版本和业务处理开关为依据确认；未确认时显示订阅中／失败。连接代次变更不能沿用上次持久 CONFIRMED。
7. 兼容接管在代码内逐股进行：必须已收到匹配的实际确认，且该股没有缺少个人订阅的 ACTIVE／COOLDOWN 规则，才撤销 `legacy_hold`。仍有个人需求时不退订；孤立生效规则阻止接管，不静默丢失行情。若希望保留兼容持有，应在最终审批时明确改为 false；该模式下最后用户取消仍可能占用名额，不能当作完整动态功能已经放开。

## 加载后只读验收

- 核对原十五股均有当前连接的实际确认，能力接口与个人列表一致；不存在“监控中但未订阅”，预算为 15／15，未启用第二条接入。
- 观察至少 90 秒心跳与错误增量，保留旧进程的历史诊断。新进程计数清零不等于 IEX 1006／历史客户端时间缺口已修复；休市无成交只算连接验收。
- 不为加载验收擅自创建近价真实规则、取消任何人的订阅、标记通知已读或制造正式触发。开市时只读观察自然首笔建立基线与后续行情；休市时将自然行情项明确保留待验。
- 验证原已保存普通实验可恢复；新模拟能力可见，但不为展示替换本人的旧实验。新的模拟跳空演示若需替换原实验，另按产品确认流程由本人决定。
- 核对正式触发、Outbox、Broker 与通知关系、消费幂等和未发送积压；新写入须来自自然 REAL 行情，历史缓存／模拟不能产生新增正式通知。
- 供应商动态增加、取消和实际额度仍须后续在**这同一条连接**上协调验证。首轮不自动验证超限，不将本机回环协议测试当作账户 PASS。

**容量限制必须告知用户：** V9 会为所有现有用户建立原十五股需求。只取消本人的某股，并不释放其他用户仍需的全局名额；兼容接管本身也不腾出第 16 个名额。新增目录外股票前，必须有最后一个合法需求取消并收到退订 ACK，或另行验证／批准提高实际额度。不得为腾名额直接改库、删除其他用户需求或停用其规则。首次实际动态增删验收需要先明确选定可变更股票及所有受影响用户，不包含在本计划的只读加载验收中。

## 失败处理与回滚

| 失败时点 | 措施 |
| --- | --- |
| 备份不完整、恢复／指纹不通过 | 不停原服务、不迁移；先解决备份问题 |
| MySQL V9／V10 失败或部分 DDL | 保持新接入未启动，保存失败库和日志。MySQL DDL 不能假设整段事务回滚；不盲目 `repair`、不编辑已执行迁移或 DROP 新表。明确检查已执行步骤后再决定修复推进或恢复 |
| 迁移成功、尚未接受任何个人需求变更 | 可保留 V9／V10，以**同版本已验证的静态兼容配置**恢复原十五股：三个功能开关 false、其余原配置不变。新管理入口关闭，个人请求数据保留；先停止失败新进程再启动回退实例，不并连 IEX |
| 接入失败／ACK 超时／拒绝 | 状态保持 PENDING／FAILED，不手工确认。先判断单次重连是否可恢复；持续失败按上一行有限回退，保留失败代次证据，不探测更多连接 |
| 已接受新增、取消、规则软删除或新正式触发／通知 | 不回到 V8 业务语义，不简单关闭动态协调器／资格保护，不恢复旧整库覆盖新事实。保留新表、持久需求和全部通知，优先修复向前；如必须短停，继续使用懂得 V9／V10、意图版本和新生成器版本的兼容构建 |
| 必须恢复截止点备份 | 仅在确认截止点后没有应保留的新事实，且明确决定执行恢复时，先恢复到**另一个空本机库**并验证，再协调切换；保留失败原库。不得直接以旧 SQL 覆盖正在变化的正式库，恢复动作需纳入当次明确批准范围 |

不依赖删除 V9／V10 表或收窄股票名称来“降级”。旧 V8 二进制没有个人取消／动态订阅语义，不能作为开放管理后的通用回退版本。Redis 是派生索引，不清空原共享实例；恢复时按现有 token／按需重建机制校验。
